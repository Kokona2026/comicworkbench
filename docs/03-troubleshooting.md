# 排错与决策规则

遇到问题先看现象，按表回到对应阶段处理，不要在后面的阶段硬修前面留下的问题。

| 现象 | 可能原因 | 处理 | 回到 |
| --- | --- | --- | --- |
| 角色脸、发型飘 | LoRA 强度偏低，或素材差异太大 | 强度提到 0.8–1.0，补素材，换更晚的 checkpoint | 阶段 2 |
| 服装或背景被锁死 | 训练过度，或素材太单一 | 选更早的 checkpoint，补换装和换背景素材 | 阶段 2 |
| 画面噪点多、细节过度 | CFG 过高，或 score 标签太强 | 降低 CFG，去掉 score 标签，加 `anime coloring`（权重 < 1） | 阶段 3 |
| 左右方向、发型细节不稳 | Anima 上角色 LoRA 的已知限制，加长训练也没改善 | 用自然语言在提示词里写明方向，不靠加步数 | 阶段 2、3 |
| 侧面和背面解剖崩 | 难视角本身容易出错 | Illustrious 加姿势 ControlNet，或 Qwen-Image 2.1 编辑 | 阶段 1、3 |
| 手部崩 | 通用问题 | Krita 局部重绘 | 阶段 3 |
| 多角色互相串属性 | 一条提示词里属性混在一起 | 分别出图再合成，或分区域重绘 | 阶段 4 |
| 训练变慢或显存溢出 | Windows 把显存溢出到内存 | 降低 batch 或分辨率，开 gradient checkpointing，关闭占显存的程序 | 阶段 2 |
| 视频里脸漂移 | 多次接力后累积误差 | 叠加角色 LoRA，缩短单段，换更清晰的首帧 | 阶段 5 |
| 视频 4 步反而比 8 步慢 | 个别显卡上的已知现象 | 两种设置都实测，选更快的 | 阶段 5 |

## 工程侧排错

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 控制台页面打不开 | `python app\server.py` 的横幅输出 | 端口被占用时会自动顺延 20 个端口，看横幅里的实际端口 |
| 双击快捷方式后多了个窗口/端口变了 | `Get-NetTCPConnection -State Listen -LocalPort 8766,8767` | 新版会**复用**已运行的实例并只打开浏览器；旧窗口可用 `--force-port` 另起一个 |
| 宽屏下页面挤成中间一条、像旧版 | 地址栏是否带 `?v=`；`Ctrl+F5` | 启动时打开的地址带 `?v=<页面 mtime>`，页面一改就换 URL；仍旧则是浏览器没刷新 |
| 审计报「重复 ComfyUI 实例」 | `app/checks.ps1 -Mode processes` | 现在只认 `main.py` 或 `ComfyUI\` 路径；若仍报，按 evidence 里的 pid 停掉多余进程 |
| 审计报「ComfyUI 未定位」 | `STUDIO_COMFYUI_DIR` | 安装便携版后 `setx STUDIO_COMFYUI_DIR <path>`，或把 ComfyUI 放到项目根 |
| 审计报「节点未注册」 | `/object_info` | `scripts\20-verify-workflow.ps1` 列出缺哪个节点包，装上或改节点名 |
| PowerShell 脚本乱码 | 编码 | 脚本必须 ASCII-only；`tests\lint_test.py` 会拦 |
| 停止后显存没释放 | 残留子进程 | `11-stop-comfyui.ps1` 按端口反查监听进程再杀；`scripts\stop.ps1` 会打印 VRAM |
| 权重文件校验失败 | 下载不完整 | `02-fetch-models.ps1` 按 `min_bytes` 比对，小于阈值视为截断，重新下载 |

## 决策规则

1. **数值以本机实测为准。** 文档和社区给的都是起点，最终值写进
   `reports/baseline.json` 与 `config/params.json`。
2. **步数以样图为准，不以数字为准。** 社区报告的成熟步数从 1.8k 到 12k 都有，
   差异来自数据集与训练器，不是步数本身。
3. **验收不过就回退，不硬修。** 后阶段修前阶段的问题只会把误差固化到产出物里。
4. **只绑定回环。** 任何需要 `--listen 0.0.0.0` 的场景都要先想清楚暴露面。
